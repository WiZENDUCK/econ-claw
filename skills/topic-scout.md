# 选题雷达（topic-scout）

## 作用

当你收到政策变化、市场异动、制度改革、行业冲击、企业行为变化或模糊研究想法时，使用这个 skill 将现实问题转化为**可研究、可变量化、可设计识别策略**的候选题目。

这个 skill 负责研究流程的最前端：把“现象”变成“问题”。

---

## 什么时候用

在以下场景优先使用：
- 用户说“这个能不能做成论文题目”
- 用户给你一条政策、新闻或市场现象，想判断研究价值
- 用户有一个直觉，但表达很模糊
- 用户想同时看到研究问题、变量方向、数据源和设计候选

---

## 不要什么时候用

以下情况不要把它当主 skill：
- 用户已经有明确题目，只需要文献综述 → 优先用 `lit-reviewer`
- 用户已经在比较 DID / IV / RDD → 优先用 `design-doctor`
- 用户已经有结果表，想写论文 → 优先用 `paper-drafter`

---

## 输入

输入通常包括以下一种或多种：
- 一条政策、新闻、监管变化
- 一个市场现象或企业行为
- 一个研究直觉或模糊想法
- 一个初步题目

如果信息不完整，你要主动补齐以下结构：
- 研究对象是谁
- 变化发生在什么时候
- 潜在影响是什么
- 可能的比较组在哪里
- 数据可能从哪里来

---

## 输出

标准输出尽量包含：

### 1. 候选研究问题
给出 1-3 个可执行的问题版本，而不是只抛一个大而空的题目。

### 2. 变量方向
至少识别：
- 潜在因变量
- 核心解释变量 / 处理变量
- 可能的机制变量
- 可能的异质性维度

### 3. 初步识别设计候选
例如：
- DID
- IV
- RDD
- Panel FE
- Event Study
- 匹配 + 回归

### 4. 数据源建议
给出最小可行数据方案，优先指出：
- 哪些数据是必须的
- 哪些数据是可选增强项
- 是否需要 CSMAR / 公告 / 政策文本 / 宏观数据

### 5. 研究价值判断
简要说明该题目的潜在贡献来自：
- 现实重要性
- 文献空白
- 制度背景
- 数据可得性
- 识别强度

---

## 建议工作顺序

1. 先识别现实现象的核心变化
2. 再判断变化可能影响谁、影响什么结果
3. 再把问题压缩成可研究表达
4. 再给变量与设计候选
5. 最后再判断研究价值与可行性

不要一上来就写漂亮题目，先把研究骨架立住。

---

## 质量要求

你输出时应避免：
- 只给一个空泛题目
- 变量不落地
- 设计候选与问题不匹配
- 完全不考虑数据可得性
- 把新闻价值错当成研究价值

---

## 常见串联

最常见的后续链路：
- `topic-scout` → `lit-reviewer` → `design-doctor`
- `topic-scout` → `design-doctor` → `csmar-data`

---

## 示例

### 输入
“注册制改革之后，分析师覆盖是不是更偏向成长型公司？这个能做吗？”

### 输出方向
- 候选题目：注册制改革是否改变分析师资源配置偏好
- 因变量：分析师覆盖数量 / 跟踪频率
- 处理变量：注册制实施后 × 成长型企业特征
- 机制：信息披露改善、市场关注度变化、投行业务协同
- 数据源：CSMAR 分析师跟踪、上市公司财务、板块与注册制时间信息
- 设计候选：DID / Event Study / 分组异质性
