# RDD 分析引擎（run-rdd）

## 作用

当研究设计依赖阈值、断点、评分规则或制度门槛时，使用这个 skill 组织断点回归分析。

---

## 什么时候用

- 存在明确 cutoff / threshold
- 处理状态由阈值附近规则决定
- 用户需要 sharp / fuzzy RDD 框架

---

## 不要什么时候用

- 没有明确断点
- 阈值只是事后人为划分
- 样本无法支撑断点附近局部比较

---

## 核心任务

1. 明确 running variable 与 cutoff
2. 判断 sharp / fuzzy 设计
3. 组织局部线性估计与带宽选择
4. 安排密度检验、协变量连续性、伪断点检验
5. 组织图形展示与局部效应解释

---

## 建议工作顺序

1. 先讲断点制度逻辑
2. 再定义 running variable
3. 再做主估计
4. 再补图与诊断

---

## 重点检查

- 是否存在断点操控
- 断点附近样本是否足够
- 结论是否被错误外推

---

## 质量要求

- 不能只跑一个带宽
- 不能没有 McCrary / 连续性意识
- 不能把局部效应写成整体效应

---

## 常见串联

- `design-doctor` → `run-rdd`
- `run-rdd` → `robustness` / `make-table`

---

## 输出

- RDD 设计说明
- 主估计与稳健性结构
- 图形与诊断检验清单
